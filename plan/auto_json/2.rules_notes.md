# 🇨🇳 Notes(注释) & Vocabulary JSON 생성 규칙 (AI Sidekick)

> ⚠️ **공통 규칙:** `0.rules_common.md` 참조 (병음, `<b>` 태그, JSON 병합, 구어체 생성, 코드 참조)

## 🎯 목적
학습 자료의 **'注释(문법/노트)'** 및 **'生词(새 단어)'** 이미지를 분석하여, `grammar` 및 `vocabulary` 배열을 생성한다.

## 🛠️ 데이터 구조

### Grammar (문법)

| 필드 | 타입 | 설명 |
|------|------|------|
| `point` | string | 문법 핵심 표현 (예: `"不仅……也/还……"`) |
| `explanation` | string | 용법에 대한 명확한 설명 |
| `formal_examples` | Example[] | 교재에 등장하는 **모든** 중국어 예문 |
| `colloquial_pattern` | string | 원어민이 더 자주 쓰는 대체 패턴 (예: `不仅` → `不光`) |
| `colloquial_examples` | Example[] | AI가 생성한 실전 구어체 문장 배열 |
| `nuance` | string | 표준 vs 구어체 미묘한 차이 설명 |

**Example 객체:** `{ chinese, pinyin, translation }`

### Grammar translation pack

`grammar`를 생성/수정할 때 `translations.grammar[point]`는 반드시 아래 구조를 따른다.

```json
{
  "formal_translation": { "ko": "...", "ja": "...", "en": "..." },
  "colloquial_translation": { "ko": "...", "ja": "...", "en": "..." },
  "formal_examples": [
    { "translation": { "ko": "...", "ja": "...", "en": "..." } }
  ],
  "colloquial_examples": [
    { "translation": { "ko": "...", "ja": "...", "en": "..." } }
  ]
}
```

언어별 객체를 최상위에 두는 형태(`ko.formal_translation`, `ja.formal_translation`, `en.formal_translation`)는 앱 스키마와 맞지 않으므로 사용하지 않는다.

### Vocabulary (단어)

| 필드 | 타입 | 설명 |
|------|------|------|
| `word` | string | 단어 한자 |
| `pinyin` | string | 정확한 성조 병음 |
| `meaning` | string | 의미 (품사 접두어 포함: `"n. law"`) |

Vocabulary/proper noun의 원본 저장 위치와 translation pack 저장 위치를 구분한다. 원본 단어는 `vocabulary[]` 또는 `texts[].proper_nouns[]`에 저장하고, 다국어 의미는 각각 `translations.vocabulary[word]`, `translations.properNouns[word]`에 저장한다.

## ⚙️ 처리 가이드

### Grammar 이미지 분석
- 문법 포인트의 번호/제목/설명을 정확히 매칭
- **교재에 적힌 모든 중국어 예문을 빠짐없이 `formal_examples`에 담는다**
- 예문이 여러 줄이면 전체를 하나의 예문으로 저장
- 설명 본문 안의 짧은 중국어 문장도 예문 성격이면 누락하지 않는다
- 기존 JSON에 예문 앞부분만 있으면, 이미지 기준으로 나머지 보강
- `explanation`은 축약하지 말고, 이미지의 핵심 조건/위치 규칙/사용 범위를 그대로 반영
- `grammar`를 추가/수정하면 `translations.grammar[point]`도 함께 생성/갱신하고, `formal_examples` 및 `colloquial_examples` 번역 배열의 개수와 순서를 원본과 맞춘다
- `translations.grammar[point].formal_examples[i]`와 `colloquial_examples[i]`는 반드시 `{ translation: { ko, ja, en } }` wrapper를 사용한다. `{ ko, ja, en }`만 직접 넣으면 불완전한 pack으로 처리된다.

### 비교/설명형 이미지 (`比一比 Compare`, `A vs B`, `区别`, `不同점`, `相同점`)
- 일반 문법 포인트로 임의 변환 금지
- `point`는 비교 항목임을 드러내는 이름 (예: `"刚 vs 刚才"`, `"尤其 vs 特别"`)
- `Similarity`/`Differences`/번호별 비교 설명을 `explanation`에 구조적으로 보존
- 비교 이미지의 모든 중국어 예문을 `formal_examples[]`에 빠짐없이 저장
- `colloquial_examples[]`는 보조 역할만, 교재 예문 대체 불가

### 확장/동자어 이미지 (`扩展`, `同字词`)
- 일반 문법 패턴으로 임의 변환 금지
- `point`는 `同字词：感`처럼 확장 노트임을 명확히 표시
- 이미지의 단어군을 `explanation`에 보존, 모든 중국어 예문을 `formal_examples[]`에 저장
- 확장/동자어 항목도 일반 grammar와 동일하게 `translations.grammar[point]`를 생성한다. 특히 `formal_examples.length`와 번역 pack의 `formal_examples.length`가 반드시 같아야 한다.

### 창의적 구어체 생성
- 단순히 교과서 문장을 바꾸는 수준을 넘어, 해당 상황에서 원어민이 느낄 법한 감정이나 최신 트렌드를 반영한다
- `贼`, `给力`, `领증` 등 트렌디하고 생생한 어휘 사용 권장
- 구어체는 가장 대표적인 예문 하나를 기반으로 생성하거나 포인트 자체를 활용한다
- 비교/확장/동자어 항목에서는 교재 원문 보존이 우선, 구어체는 보조 역할만 하며 원문 설명이나 교재 예문 대체 불가

### 대화문(A/B) 처리
- 대화 패턴(`A: ..., B: ...`)이 등장하면 **`<br/>` 태그**로 줄바꿈
- `chinese`, `pinyin`, `translation` 모든 필드에서 대화 주체 변경 시(B: 시작 전) `<br/>` 삽입

## ✅ Notes 생성 후 필수 검증

- 모든 `grammar[].point`에 대해 `translations.grammar[point]`가 존재
- `formal_translation`, `colloquial_translation` 각각 `ko`, `ja`, `en` 포함
- `formal_examples` 원본/번역 pack 개수 일치
- `colloquial_examples` 원본/번역 pack 개수 일치
- 각 예문 번역은 `{ translation: { ko, ja, en } }` 형태
