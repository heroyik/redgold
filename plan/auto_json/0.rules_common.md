# 🇨🇳 공통 규칙 (AI Sidekick)

> **⚠️ 기준 스키마:** `plan/lesson-schema-canonical.md` 참조
> **기준 데이터:** `data/lesson1.json`
> **실행 시 로드 대상:** Lesson JSON 생성/수정 작업에는 `0~3.rules_*.md`만 포함한다. `rules-optimization-spec.md`는 설계/기록 문서이므로 작업 프롬프트에 포함하지 않는다.

이 규칙은 중국어 학습 자료의 이미지를 분석하여 앱에 필요한 JSON 파일을 생성할 때 **모든 도메인(课文, 注释/生词, Mastery)에서 공통으로 적용되는 표준 규칙**을 정의한다. 각 도메인별 고유 규칙은 별도 파일(`1.rules_kewen.md`, `2.rules_notes.md`, `3.rules_mastery.md`)에서 확인한다.

기본 생성 기준은 실제 앱 데이터인 `data/lesson1.json`의 구조다. `plan/lesson-schema-canonical.md`는 스키마 확인이 필요할 때 참조하되, 실행 중에는 `lesson1.json`과 현재 `lesson{N}.json`의 필드 구조를 우선한다.

---

## 1. 하이라이트 규칙 (`<b>` 태그)

핵심 문법 패턴은 반드시 `<b>` 태그로 강조한다.

- **Standard/Formal**: `<b>` 태그 → **Imperial Red (#8B0000)** — `TextSection.ts`(课文), `GrammarCard.ts` 앞면
- **Colloquial/구어체**: `<b>` 태그 → **Gold (#DAA520)** — `GrammarCard.ts` 뒷면, Mastery

모든 도메인(texts, grammar, key_sentences)에서 동일하게 적용한다.

---

## 2. 병음 표기 규칙

- 성조 기호 정확히 사용 (ā, á, ǎ, à)
- `ü`는 `ü`로 표기 (v로 대체하지 않음)
- 단어별 띄어쓰기 (예: `nǐ hǎo` vs `nǐhǎo`)
- 문장 부호 뒤에는 공백

---

## 3. JSON 병합 로직

- 기존 파일 읽기 → 해당 ID/point 기준 교체(Replace) 또는 추가(Append)
- `lessonId`와 `title` 유효성 상단에서 먼저 확인
- `texts`는 `id` 기준으로 기존 데이터를 업데이트하거나 새 항목을 생성
- `texts[].proper_nouns`는 해당 text 내부의 원본 고유명사 배열이며, 중복 체크는 `word` 기준
- `texts[].proper_nouns`는 본문에 고유명사가 없으면 생략 가능하다. 생략된 경우 검증 실패로 보지 않는다. 단, 배열이 존재하면 모든 항목은 `word`, `pinyin`, `meaning`을 갖고 `translations.properNouns[word]`도 있어야 한다.
- `key_sentences`는 문장 배열 순서를 보존하고, 기존 항목 수정 시 동일 위치를 업데이트
- `grammar`는 `point`를 기준으로 기존 데이터를 업데이트하거나 새 항목을 생성
- `vocabulary`는 중복 체크 후 끝에 추가
- 새 `grammar` 항목을 추가하면 `translations.grammar`에도 같은 키를 추가한다
- 새 `vocabulary` 항목을 추가하면 `translations.vocabulary[word]`에도 같은 키를 추가한다
- 새 `texts[].proper_nouns` 항목을 추가하면 `translations.properNouns[word]`에도 같은 키를 추가한다
- `grammar[].formal_examples.length`와 `translations.grammar[point].formal_examples.length`는 반드시 일치
- `grammar[].colloquial_examples.length`와 `translations.grammar[point].colloquial_examples.length`도 반드시 일치

---

## 4. 구어체 생성 원칙

- 원어민이 실제로 사용하는 생생한 표현 (賊, 给力, 领증 등 트렌디 어휘)
- 해당 상황에서 느낄 법한 감정/트렌드 반영
- 비교/확장/동자어 항목에서는 교재 원문 보존이 우선, 구어체는 보조 역할만

---

## 5. 번역 품질 기준

### 한국어 (KO)
- 중국어 직역보다 일상적 자연스러운 문맥 우선
- 교과서 표현(Formal)은 해요체, 구어체는 친근한 말투
- 중국어 관용구는 한국어 대응 표현으로 의역

### 일본어 (JA)
- 적절한 한자/가나 비중 유지
- Formal: です/ます, Colloquial: だ/である 또는 회화체

### 영어 (EN)
- 자연스러운 영어 문체, 직역 지양

---

## 6. 코드 참조

- `TextSection.ts`: 한자 수/병음 길이 기반 오디오 하이라이트 타이밍 자동 계산
- `GrammarCard.ts`: 앞면(Formal) ↔ 뒷면(Colloquial) 뒤집기 구조
- `translateLessonData`: translations 필드 기반 동적 로케일 매핑
- `lessonTranslations.ts`: 코드 내 하드코딩 → JSON 동적 처리로 전환

---

## 7. 다국어(로케일) 규칙

### JSON 구조
- `translations` 객체: vocabulary, properNouns, grammar, keySentences, texts, lessonTitle, textTitles
- `lessonTitle`, `textTitles` 필수
- `translations.vocabulary`, `translations.grammar`, `translations.keySentences`, `translations.texts`, `translations.lessonTitle`, `translations.textTitles`는 모든 완성 레슨에서 필수
- `translations.properNouns`는 고유명사가 하나라도 있는 레슨에서는 필수다. 고유명사가 없는 레슨에서는 빈 객체라도 허용한다.
- 원본 JSON 필드는 snake_case를 쓴다: 예) `texts[].proper_nouns`, `key_sentences`
- translation pack 필드는 camelCase를 쓴다: 예) `translations.properNouns`, `translations.keySentences`
- `translations.texts` line key는 반드시 **0-based index**
- 각 translation 객체는 `ko`, `ja`, `en` 모두 포함
- translation pack의 표준 형태는 항상 `{ ko, ja, en }` 또는 `{ translation: { ko, ja, en } }`이다. `{ ko: {...}, ja: {...}, en: {...} }`처럼 언어를 최상위 wrapper로 두지 않는다.

### 동적 로케일 로직
1. `lesson{N}.json` 로드
2. `translateLessonData(data, language)` 호출
3. `translations` 필드에서 해당 언어 번역으로 원본 필드 덮어쓰기
4. 번역 없으면 원본(en) 유지

### 검증 체크리스트
- `lessonId`, `title`, `vocabulary`, `grammar`, `texts`, `key_sentences`, `translations`가 존재
- `translations.lessonTitle`이 `ko`, `ja`, `en`을 모두 포함
- `translations.textTitles[text.id]`가 모든 `texts[].id`에 대해 존재하고 `ko`, `ja`, `en`을 모두 포함
- `translations.vocabulary[word]`가 모든 `vocabulary[].word`에 대해 존재하고 `ko`, `ja`, `en`을 모두 포함
- `texts[].proper_nouns`는 optional이다. 없으면 정상, 있으면 각 `word`에 대해 `translations.properNouns[word]`가 `ko`, `ja`, `en`을 모두 포함
- `translations.texts`는 모든 `texts[].id` 포함
- 각 `texts[].content[i]`마다 `lines[i].translation` 존재
- `translations.texts[text.id].lines`는 원본 `texts[].content`와 개수 및 0-based 순서가 일치
- `translations.grammar[point].formal_examples`는 원본 `grammar[].formal_examples`와 개수 및 순서가 일치
- `translations.grammar[point].colloquial_examples`는 원본 `grammar[].colloquial_examples`와 개수 및 순서가 일치
- `translations.keySentences`는 원본 `key_sentences`와 개수 및 순서가 일치하고, 각 항목에 `translation`, `colloquial_translation`, `context`가 모두 존재
- `key_sentences[]` 원본 항목에도 `sentence`, `pinyin`, `translation`, `colloquial_equivalent`, `colloquial_pinyin`, `colloquial_translation`, `context`가 모두 존재
- 독백(`speaker: "独白"`)도 `lines["0"]`에 번역 필수
- 1-based key 사용 금지 (0-based만 허용)
- `ko`, `ja`, `en` 3개 언어 모두 포함
