# 🇨🇳 Notes(注释) & Vocabulary JSON 생성 규칙 (AI Sidekick)

> **⚠️ 기준 스키마:** `plan/lesson-schema-canonical.md` 참조
> **기준 데이터:** `data/lesson1.json`

## 🎯 목적
학습 자료의 **'注释(문법/노트)'** 및 **'生词(새 단어)'** 이미지를 분석하여, `grammar` 및 `vocabulary` 배열을 풍성하고 실전적인 데이터로 생성한다.

## 🛠️ 핵심 요구사항 및 로직
1.  **Grammar(문법) 데이터 구조** (canonical 스키마 기준):
    *   `point`: 문법 핵심 표현 (예: "不仅……也/还……")
    *   `explanation`: 용법에 대한 명확한 설명.
    *   **Formal Side (표준 - 교재 예문 전부 포함)**:
        *   `formal_examples`: 이미지에 등장하는 **모든 중국어 예문**을 **객체 배열**로 수집.
            *   `chinese`: 교재 예문 원문. 문장 일부만 저장하지 말고, 예문 번호 안의 중국어 문장 전체를 보존한다. 패턴은 `<b>` 태그로 강조.
            *   `pinyin`: 예문 병음.
            *   `translation`: 예문 번역.
    *   **Colloquial Side (실전 구어체 - Enrichment)**:
        *   `colloquial_pattern`: 원어민이 실제로 더 자주 쓰는 대체 패턴 (예: `不仅` -> `不光`).
        *   `colloquial_examples`: **AI가 독자적으로 생성한 실전 문장 배열.** `贼`, `给力`, `领证` 등 트렌디하고 생생한 어휘 사용 권장. 패턴은 `<b>` 태그로 강조.
            *   `chinese`: 구어체 문장 (<b> 태그로 핵심 패턴 강조).
            *   `pinyin`: 구어체 문장 병음.
            *   `translation`: 구어체 문장 번역.
    *   `nuance`: 표준 버전과 구어체 버전의 미묘한 차이 설명 (예: "친구 사이에서 훨씬 더 감정을 실어 표현할 때 사용").

> **⚠️ 주의:** 이전 구버전 스키마에서는 `colloquial_version`(단일 문자열), `colloquial_pinyin`, `colloquial_translation` 필드를 사용했으나, 현재 **`colloquial_examples: Example[]` 배열 형식**으로 변경되었습니다.

2.  **Vocabulary(단어) 데이터 구조**:
    *   `word`: 단어 한자.
    *   `pinyin`: 정확한 성조 병음.
    *   `meaning`: 의미. 품사 정보(n., v., adj.)가 있으면 접두어로 포함 (예: "n. law").

3.  **UI 렌더링 호환성**:
    *   `GrammarCard.ts`는 앞면(Formal)과 뒷면(Colloquial)을 뒤집으며 보여주는 구조이다.
    *   뒷면의 `<b>` 태그는 CSS에 의해 자동으로 **Gold (#DAA520)** 색상으로 표시되므로, 강조하고 싶은 구어체 패턴에 반드시 적용한다.

## ⚙️ 상세 처리 가이드
1.  **이미지 분석**: 문법 포인트의 번호와 제목, 설명을 정확히 매칭하며, **교재에 적힌 모든 중국어 예문을 빠짐없이 `formal_examples` 배열에 담는다.**
    *   예문이 여러 줄로 이어지면 전체 줄을 하나의 예문으로 저장한다.
    *   설명 본문 안에 들어간 짧은 중국어 문장도 예문 성격이면 누락하지 않는다.
    *   기존 JSON에 예문의 앞부분만 들어 있으면, 이미지 기준으로 나머지 중국어 문장·병음·번역을 보강한다.
    *   `explanation`은 “Not only... but also...”처럼 축약하지 말고, 이미지의 영어/중국어 설명에서 핵심 조건, 위치 규칙, 사용 범위를 그대로 반영한다.
2.  **비교/설명형 이미지 처리**:
    *   `比一比 Compare`, `A vs B`, `A / B`, `区别`, `不同点`, `相同点` 성격의 이미지는 일반 문법 포인트로 임의 변환하지 않는다.
    *   `point`는 기존 `刚 vs 刚才`처럼 비교 항목임을 드러내는 이름으로 저장한다. 예: `刚 vs 刚才`, `尤其 vs 特别`.
    *   이미지의 `Similarity`, `Differences`, 번호별 비교 설명을 `explanation`에 구조적으로 보존한다.
    *   비교 이미지 안의 모든 중국어 예문을 `formal_examples[]`에 빠짐없이 저장한다. AI가 만든 임의 예문으로 대체하지 않는다.
    *   비교 항목의 `colloquial_examples[]`는 보조 예문으로만 둔다. 비교 설명 자체를 흐리거나 교재 예문을 대체하면 안 된다.
3.  **확장/동자어 이미지 처리**:
    *   `扩展`, `Expansion`, `同字词`, `Words with the Same Character` 이미지는 임의로 일반 문법 패턴으로 바꾸지 않는다.
    *   전용 최상위 필드가 없으면 앱 호환을 위해 `grammar` 항목으로 추가하되, `point`는 `同字词：感`처럼 확장 노트임을 명확히 표시한다.
    *   이미지에 제시된 단어군을 `explanation`에 보존하고, 모든 중국어 예문을 `formal_examples[]`에 저장한다.
    *   A/B 대화 예문도 일반 예문과 동일하게 전체 중국어·병음·번역을 저장한다.
4.  **창의적 구어체 생성**: 단순히 교과서 문장을 바꾸는 수준을 넘어, 해당 상황에서 원어민이 느낄 법한 감정이나 최신 트렌드를 반영한 문장을 생성하라. (구어체는 가장 대표적인 예문 하나를 기반으로 생성하거나 포인트 자체를 활용한다.)
    *   단, 비교/확장/동자어 항목에서는 교재 원문 보존이 우선이다. 구어체 예문은 보조 역할만 하며, 원문 설명이나 교재 예문을 대체하지 않는다.
5.  **데이터 정규화**:
    *   병음 성조 기호(ā, á, ǎ, à)를 정확히 사용한다.
    *   불필요한 공백이나 특수문자를 제거하여 JSON 순수성을 유지한다.
    *   `ü`는 `ü`로 표기 (v로 대체하지 않음).
6.  **병합 로직**:
    *   새로운 단어는 `vocabulary` 배열 끝에 추가하되 중복을 체크한다.
    *   문법은 `point`를 기준으로 기존 데이터를 업데이트하거나 새 항목을 생성한다.
    *   새 `grammar` 항목을 추가하면 `translations.grammar`에도 같은 키를 추가한다.
    *   `grammar[].formal_examples.length`와 `translations.grammar[point].formal_examples.length`는 반드시 일치해야 한다.
    *   `grammar[].colloquial_examples.length`와 `translations.grammar[point].colloquial_examples.length`도 반드시 일치해야 한다.

7.  **대화문(A/B) 처리 규칙**:
    *   예문에 대화 패턴(`A: ..., B: ...`)이 등장할 경우, 가독성을 위해 **`<br/>` 태그**를 사용하여 줄바꿈을 처리한다.
    *   `chinese`, `pinyin`, `translation` 모든 필드에서 대화 주체가 바뀔 때마다(B: 시작 전) `<br/>`를 삽입한다.
